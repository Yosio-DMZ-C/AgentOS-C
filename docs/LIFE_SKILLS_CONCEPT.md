# Core Life Skills — 将来構想と協力者募集（2026-10）

> **Concept / Invitation for Contributors：未実装・品質未検証。**
> AgentOS-Cの当面の開発優先順位は**KB本体の機能、初回導入、手動同期、AI間移行、復旧**です。Life Skillsはその土台が整うまで実装を保留し、構想と実験成果を公開して協力者を募ります。

## 目的と分離

目指すのは「人生でより良い結果につながる選択を、本人が行えるよう支援すること」。AIが正解を決めたり、科学の勝者を宣言したりする仕組みではありません。

- **KB本体**：原本・記憶・履歴・手順・状態・版の保存と再開。Life Skillsがなくても動作する。
- **Life Skills**：必要な判断時だけ利用する交換可能な軽量モジュール。初回インストールの必須依存にしない。
- **[共有知](https://github.com/Yosio-DMZ-C/AgentOS-C-Shared-Knowledge)**：主要な主張、支持根拠、反論、未解決点、公開発言者を比較。主張比較 `claim_map` と行動推奨 `playbook` は別審査。
- **個人文脈**：本人の嗜好や過去の判断は「希望・条件」であって、外部事実の証拠ではない。共有側へ自動送信しない。

## 軽量な「全体感チェック」案

重要な選択で、必要な視点だけを内部確認する。

1. **前提**：質問の前提や暗黙の選択肢に見落としはないか。
2. **視野**：主要見解、有力な反論、新たな研究仮説、別の解決策はないか。
3. **整合性**：結論を左右する数字、条件、現行制度、科学情報に重大な矛盾はないか。
4. **個人への適合**：本人の目的・制約・失敗の損失・見直す条件と合うか。

回答の**口調・構成・長さ・見出し・結論・専門家の人数を固定しない**。すべての回答に検証や警告を強制しない。主流説と新説を同じ重みで扱う「両論併記」も強制しない。明確に反証された説を有力説として扱わない一方、根拠のある探索的仮説は不確実性を分けて検討する。

Consensus、Kialo、Britannica ProCon、DebateGraph、AllSides、一次論文、公的情報は**探索先の候補**。特定サービスの結論を科学界の確定的な合意と見なさない。専門家・研究者・YouTube等の参考情報は、実際の発言・時点・専門領域とともに必要時だけ案内する。肩書・再生回数は根拠の代わりにならない。

## 数値検査は「もっと考えろ」ではなく実計算

数値が判断を左右するなら、利用可能な演算ツールで検算する。実行できない場合は結果を捏造しない。計算が正しいことと、前提金利・税制・本人への適合が正しいことを混同しない。

限定試作：[計算尺 Draft PR #1](https://github.com/Yosio-DMZ-C/AgentOS-C/pull/1)（住宅購入の現金残高、必要予備資金、元利均等の概算）。本体へは未導入。

## 2026-10-09までの比較実験と限界

| 題材 | 観察 | 未解決 |
|---|---|---|
| 架空の住宅購入、通常AIと指示文追加 | 一部で専門家・判断条件が整理されたが、数値不整合は両方に存在 | 指示文だけで検算の品質を保証できない |
| 架空の断食・オートファジーの相談 | 目的から見て別の選択肢や根拠の限界を提示する例があった | 研究の正確性を保証しない、小標本 |
| 外部計算プログラム | GrokはNode.jsで実行できたと報告、GeminiとPerplexityでは取得段階で失敗 | Grokの実行成功は本人が提示した自己報告。各AI全般への一般化不可 |

**メモリ・嗜好によってAIが利用者の考えに迎合し、視野が狭くなるのを防げるか**は、価値がありそうな未検証仮説です。有効性が確立したとは主張しません。

## 協力者を募集しています

高度なモデルや自動テスト環境を利用できる人による検証を歓迎します。ただし**有料契約は参加資格ではなく、高価格＝高品質とも見なしません**。参加は小さなIssue／Draft PRから可能です。

特に必要な協力：

1. **再現可能なA/Bテストの設計**：同じ質問・モデル・検索設定で通常版と補助版を比較。メモリ・嗜好の有無も切り分ける。
2. **自動・半自動評価**：テストケースの版管理、出力収集、根拠照合、数値検算、回帰判定、使用コストの計測。AIによる採点だけで真偽を確定しない。
3. **科学・法律・実務レビュー**：主要な主張の反証、適用年度、独立した根拠、利益相反、誤りによる損失の評価。
4. **専門家・公開コンテンツ接続**：確認済みの発言・根拠・異論から関連資料に進める仕組み。紹介しただけで「専門家が監修した」と記録しない。
5. **小さいモデル・手動同期環境への適用**：実行手段がなくても安全に未確認を表明し、利用可能なら計算・検索手段へ切り替える。

### テストや設計提案をするとき

「課題／仮説」「架空の同一ケースと対照」「モデル・ツール・メモリ設定・実施日」「重要な誤りと見落としの判定基準」「実行ログ／結果」「未実施／未確認」「提案の保守コスト」を示してください。重大な誤りの見逃しや過剰な慎重さも検査対象にします。

実在ユーザーの健康・家族・購買情報、非公開チャット、個人KB、認証情報を公開PRや外部AIへ投入しないでください。AI生成の推論と確認済みのソースを区別し、原文の無断転載をしないでください。

## 今は何を優先するか

1. **Foundation F1**：初回の「実行 → 保存先 → 進めて」から実ファイル生成・読戻し・変更・再開までの実動作。
2. **Foundation F2**：直接書込不能AIのZIP往復同期、接続可能になったときの移行、失敗時の復旧。
3. **Foundation F3**：各AI環境の能力差を少数の再現テストで記録。
4. **その後**：低負担の評価方法と有効な協力者が揃った時点でLife Skillsを再検討。
